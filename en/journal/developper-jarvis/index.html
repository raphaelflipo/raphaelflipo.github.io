Developing Jarvis to find its model offline

A saved conversation and a downloaded model serve different needs. Tests have to follow both.

Move between versions

Jarvis’s local-app directory is the source for the portfolio copy. A check compares published files with the reference revision. When the engine cache changes, tests verify that complete files and conversation history remain accessible. Resuming a transfer needs another scenario: interrupt the download, inspect the next request offset and verify the final bytes.

Ask for a reply after disconnecting

A simulated worker helps exercise the Cancel button and interface messages. Testing generation requires loading real weights and obtaining text. The offline test follows a complete initial installation, disconnects the network and requests another reply. Availability also depends on the storage the browser grants to this origin.
